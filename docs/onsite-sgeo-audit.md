# SGEO 统一诊断规则（onsite-sgeo-v2）

`site_geo_audit` 沿用原任务标识，产品名称为“网站 SGEO 诊断”。评分版本升级至 `onsite-sgeo-v2`，与 `onsite-geo-v3` 同步共享升级后的底层检测能力与维度顺序。不再并列输出两套报告，也不对 SEO、GEO 总分或维度分做平均。

## 六维与检查归属（29 项唯一检查 · 100 分）

| 维度 | 权重 | 唯一检查 |
|---|---:|---|
| 可获取：访问、抓取与性能 | 20% | SGEO-001 HTTP/HTTPS/主域/重定向(4)；002 Robots.txt与AI检索爬虫/Content-Signal(5)；003 CDN/WAF与AI爬虫探针(4)；025 TTFB与HTML耗时(3)；027 移动视口(2)；028 HTML体量与正文信噪比(1)；029 图片资源与加载策略(1) |
| 可发现：页面发现与索引 | 15% | SGEO-005 语义导航内链(2)；006 XML Sitemap质量与发现覆盖(3)；007 Canonical/跳转(3)；008 索引与摘要指令(3)；024 llms.txt与Markdown直出(2)；026 URL静态化与语义规范(2) |
| 可理解：正文读取与信息提取 | 18% | SGEO-009 初始HTML直出与反CSR空壳(8)；010 语义表格与关键载体(6)；011 原始与渲染DOM一致性(4) |
| 可识别：元数据与实体语义 | 12% | SGEO-021 TDK与语言元数据(2)；022 实体命名/@id与sameAs关联(3)；023 适用Schema.org及正文对齐(5)；030 多语言hreflang(2) |
| 可引用：内容价值与答案适配 | 20% | SGEO-012 单H1与主题对应(5)；013 首段结论与问答摘要(5)；014 标题层级与段落自包含(4)；015 页面任务核心信息(4)；016 具象量化与低冗余(2) |
| 可信赖：主体、依据与时效 | 15% | SGEO-017 官方主体/责任团队(4)；018 关键主张出处(5)；019 机器可读日期/版本/报价(4)；020 跨页实体与事实一致性(2) |

共 29 项检查、满分 100 分（原 `SGEO-004` 多时段抓取稳定性移入持续观测层，避免单次扫描长期卡在 `unverified`）。标题、内链、Schema、图片替代文本等重叠检查各自只有一个计分归属。

规则定义以 `app/services/audit/sgeo.py` 的 `DIMENSIONS`、`RULES` 为准；在线 `/api-doc#sgeo-scoring` 逐项展示积分与修复建议，并由测试核对一致性与维度顺序。

## 计分与证据

每页独立检测。页面类型等权，同类型页面等权，失败页面保留在样本中。聚合每条检查时，仅在适用页面间归一；待核验页面仍进入证据覆盖率的分母。

- 维度分 = 已获积分 ÷ 已测积分 × 100。
- SGEO 暂定总分 = Σ（已测维度分 × 维度权重）÷ 已测维度权重之和。
- 证据覆盖率按适用维度权重加权；分数下界将未知项按 0 分、上界按满分处理。
- 不适用项从该维度的适用积分中排除；整个维度不适用时才从适用权重中排除。
- HTTP 失败、软 404、WAF/AI 爬虫拦截、robots/Content-Signal 阻止、noindex 或 CSR 空壳无核心正文等阻断独立保留。即使测得较高暂定分，状态仍为 `blocked`。
- 未测渲染保持 `unknown`；`SGEO-020` 在 ≥2 个含可比结构化实体的采样页间自动初筛冲突，单页或无结构化实体时记为 `na`。

HTML 获取耗时使用 800/1500/3000/5000ms 分档；HTML 体量与信噪比使用 250KB/500KB/1MB 启发式预算及正文占比，不冒充 Core Web Vitals。移动端只检查 viewport 声明，图片检查资源可发现性与显式高优先级/懒加载冲突。多语言在单语种无多语言路径站点自动判 `na`，多语言站点校验语法、自引用、`x-default` 与 `html lang` 一致性（互返关系需另行核验）。

`llms.txt` 与 Markdown 直出占 2 分。分析代码、社交卡片、一般安全头、纯训练授权、站外权威和平台推测不计分。纯 SEO 仍可按其独立规则使用相关支持信号。

SGEO是站内搜索与生成式检索就绪度，不代表实际收录、排名、真实爬虫访问或AI引用概率。语义规则是结构代理；AI配置不改变分值。

## 任务与结果

流程：`discovery → sgeo → observation → summary`。只采集一批页面证据，复用GEO基础检查的观察结果并补充搜索信号，不运行SEO完整评分引擎，不请求Semrush。

新任务结果包含：

- `result.sgeo.score`：统一总分；`scoring_version`、`status`、`provisional`、`score_range` 一并读取。
- `result.sgeo.dimensions`：唯一的六维评估，每项检查以 `SGEO-001` 至 `SGEO-030` 标识。
- `result.sgeo.pages`、`blockers`、`coverage`：逐页证据、阻断和覆盖率。
- `summary.sgeo_score`：统一摘要分数；`overall_score`、`combined_score`为同一分数的兼容别名。
- `result.observation`：独立观测，不计分。

新SGEO任务不再返回 `result.seo`、`result.geo`、`seo_summary`。调用方从原组合类型迁移时，应改读 `result.sgeo`。纯SEO、纯GEO和历史同步模块接口不变。

## 展示与历史兼容

沿用GEO报告的概览、问题表、完整清单、六维卡片和逐页证据样式。只显示一个总分、一张雷达图、一组六维卡片和一份行动清单；按维度和优先级筛选，保留影响、修复与验收条件。Markdown导出使用相同的统一模型。

新SGEO缓存包含SGEO版本、基础观察规则版本和渲染开关，与旧组合结果隔离。已有双分结果通过保存的页面检查和成功抓取快照重新归并为SGEO视图；未保存的新测量保持待核验。该过程不请求网络、不改写存储的旧评分。原分与新SGEO分不能直接横比，补齐新增检查需重新诊断。

独立SEO和GEO继续保留原规则与评分含义。共同基础能力的设计参考[Google对AI搜索功能的说明](https://developers.google.com/search/docs/appearance/ai-features)，具体分值和权重为本产品的诊断设计。
