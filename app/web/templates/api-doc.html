快速开始

异步任务模式

提交一个 URL，从创建任务开始。结果通过任务 ID 查询。

  1. 创建审计任务

    提交目标 URL，获取 task_id。

  2. 查询任务状态

    每隔 1–2 秒轮询，直到任务完成或失败。

  3. 读取与导出结果

    从 result 读取诊断，按需获取报告和图谱。

cURL创建网站 SEO 审计
curl -X POST \
  "http://localhost:8023/api/v1/tasks/audit" \
  -H "Content-Type: application/json" \
  -H "X-API-Token: YOUR_API_TOKEN" \
  -d '{
    "url": "https://example.com",
    "task_type": "site_seo_audit",
    "feedback_lang": "zh"
  }'
想直接发送请求？立即测试 API在交互式文档中查看完整请求与响应定义。

访问认证

启用访问保护时，请在所有 /api/v1/ 业务请求中携带有效 Token。推荐使用 X-API-Token 请求头。

请求头
X-API-Token: YOUR_API_TOKEN

兼容 X-Demo-Token 与 Authorization: Bearer <token>。在 API 调试页面点击 Authorize 填入 Token 即可。

401
Token 缺失或无效，请检查请求头。
429
Token 调用额度已用尽，请检查可用额度。

API 调用步骤

优先使用异步任务；需要独立诊断时，可直接调用单个模块。

创建审计任务

POST/api/v1/tasks/audit

提交目标 URL；site_geo_audit 对应“网站 SEO+GEO 审计”，后台异步启动 discovery → seo + GEO 六维模块 → observation → summary 流水线。若启用 build_knowledge_graph=true，会在 discovery 完成后复用同一批页面快照，异步分叉执行“结构图谱”和“实体图谱”两个子阶段。启用 full_audit=true 时会追加逐页诊断结果，且抓取严格限制在当前 URL 的 host 与语言作用域内。

请求参数

参数类型说明
url必填string目标网站 URL（自动规范化）
task_typestring"site_seo_audit"（默认）、"site_geo_audit"（网站 SEO+GEO 审计）或 "site_content_audit"
modestring"standard"（默认）或 "premium"（启用 LLM 增强）
force_refreshbooleantrue 则跳过 7 天缓存强制重新审计
target_localestring可选；用于指定目标站点语言版本，如 "nl"、"de"、"fr"。输入根域名时，系统会尝试把任务解析到对应语言 scope
feedback_langstring"en"（默认）或 "zh"；仅控制报告返回语言，不控制目标站点语言版本
full_auditboolean可选，启用后扩展抓取更多内部页并返回 page_diagnostics
max_pagesintFull Audit 范围 5–10000，默认 12；网站 SEO 审计未开启 Full Audit 时最多采样 8 页
build_knowledge_graphboolean是否在 discovery 后基于 MySQL 页面快照构建站点知识图谱；默认 false，开启后即使构建失败也不会中断审计
observationobject可选观测层输入，支持 GA4 / 来源拆分 / 人工引用观测；仅展示，不计分
llm.providerstringpremium 模式下固定 "openrouter"
llm.modelstring当前固定使用 "openai/gpt-5.6-sol"
完整请求示例
JSON
{
  "url": "https://example.com",
  "task_type": "site_seo_audit",
  "mode": "premium",
  "target_locale": "nl",
  "feedback_lang": "zh",
  "full_audit": true,
  "max_pages": 12,
  "build_knowledge_graph": false,
  "force_refresh": false,
  "llm": { "provider": "openrouter", "model": "openai/gpt-5.6-sol" }
}

抓取范围限定为当前 host 与语言路径。例如 www.ecoflow.com/de/ 只抓取 /de/，de.ecoflow.com 会作为独立站点处理。

查询任务状态

GET/api/v1/tasks/{task_id}

建议每隔 1–2 秒查询一次。当 status 为 completed 或 failed 时停止轮询。steps 实时反映各模块的执行状态。

queued→running→completed或failed
字段类型说明
statusstringqueued → running → completed | failed
progress_percentint0–100，按完成步骤数计算
cachedboolean命中缓存时为 true，直接返回历史结果
llm_model_usedboolean只有真正拿到并使用了 llm.model 的增强结果时才为 true；失败降级时为 false
resultobjectcompleted 后包含完整的 visibility / technical / content / schema / platform / observation / summary；full audit 时额外返回 page_diagnostics，并在 discovery.scope_root_url、requested_target_locale、resolved_target_locale 中标明语言作用域

获取任务图谱

可选

创建任务时设置 build_knowledge_graph=true。结构图谱与实体图谱复用同一批页面快照，独立异步构建，构建失败不会中断审计。

GET/api/v1/tasks/{task_id}/structure-graph

结构图谱：站点、页面、产品或服务、sameAs、内外链及证据关系。

GET/api/v1/tasks/{task_id}/entity-graph

实体图谱：品牌、产品名、特性、规格、使用场景及评价类文本实体。

导出审计报告

GET/api/v1/tasks/{task_id}/report

任务完成后，获取完整 Markdown 报告，用于渲染或保存为文件。仅在 status=completed 时可用。

页面证据与导出

获取任务发现的 URL、采样页面的抓取记录，以及 Excel 报告。以下 Demo 接口使用相同的 Token 访问验证。

GET/api/v1/demo/tasks/{task_id}/pages

站点链接与页面抓取记录，包括抓取时间、状态码、响应耗时及部分响应头。未采样或历史缺失的数据标记为“未记录”。

GET/api/v1/demo/tasks/{task_id}/pages/{page_id}/source

读取页面 HTML 源码。page_id 来自对应任务的链接列表；源码以纯文本展示，不随任务轮询重复传输。

GET/api/v1/demo/tasks/{task_id}/export.xlsx

导出当前任务的网站 SEO 审计 Excel 报告。

每份源码最多缓存 2 MB，超限时标记截断。缓存保存在 CACHE_DIR/page-sources。

Google 爬虫测试 API

独立运行 Googlebot 抓取、Chromium 渲染诊断，或一次返回两项测试结果。

检测清单说明

网站 SEO 审计固定运行 26 项检查，覆盖六大评分维度。清单展示诊断证据，问题清单仅收录未通过项，并按影响程度分为 P0、P1、P2。

覆盖清单

全部检查项，标记通过、待优化或不适用。

问题清单

未通过项及其优先级，帮助安排修复。

维度评分

按站点信号汇总，不等于问题数量求和。

数据来源与运行机制

查阅评分字段、数据来源、快照复用和 AI 增强的具体规则。

AI 可见性25%
  • 汇总取值：直接取 visibility.ai_visibility_score，再按 ×0.25 计入综合分
  • 计算公式：0.32 × AI crawler 放行率 + 0.40 × snapshot citability + 0.12 × llms.txt 有效性 + 0.16 × 基础实体存在
  • 数据来源：抓取 robots.txt、请求 /llms.txt、构建 snapshot 页面画像，并复用 homepage / about / service / article / case_study 的实体信号
  • 细项规则：citability 综合 answer-first、信息密度、数据点、分块结构与 FAQ / 作者 / 日期信号，输出 homepage_citability、best_page_citability 和 citation_probability
品牌权威20%
  • 汇总取值：直接取 visibility.brand_authority_score，再按 ×0.20 计入综合分
  • 计算公式：0.25 × 外链质量 + 0.25 × 品牌提及覆盖 + 0.25 × sameAs / Entity 一致性 + 0.25 × 企业信息完整度
  • 数据来源：站内品牌信号 + Schema sameAs + sitemap / canonical 一致性 + Semrush Backlinks Overview
  • 结构预留：当前仍由 visibility 产出品牌总分，但代码层已预留 BrandAuthorityService 边界，方便后续独立服务化
内容与 E-E-A-T20%
  • 汇总取值：(content_score + experience + expertise + authoritativeness + trustworthiness) / 5 后，再按 ×0.20 计入综合分
  • 内容总分：服务页深度、文章页深度、FAQ、作者、日期、量化数据、标题质量、answer-first、信息密度、分块结构、引用来源区、内联引用与链接语义共同构成
  • E-E-A-T 细项：Experience 看案例与量化结果；Expertise 看服务页/文章深度与结构；Authority 看作者、资质、sameAs 与参考来源；Trust 看联系信息、日期、更新记录与证据引用
  • 数据来源：优先复用 discovery.page_profiles，不再为了内容审计重复抓取这些关键页面
技术基础15%
  • 汇总取值：直接取 technical.technical_score，再按 ×0.15 计入综合分
  • 计算公式：HTTPS8 + SSR10 + Meta5 + Canonical5 + lang4 + uniqueH1 4 + Sitemap8 + robots 指令4 + 性能8 + 渲染阻塞8 + 安全头16 + 图片4 + OG5 + Twitter3 + hreflang4 + freshness headers4
  • 数据来源：最终 URL、首页 HTML、响应头、robots.txt、sitemap.xml
  • 细项说明：response_time_ms 已纳入正式性能评分；新增检查唯一 H1 与 ETag / Last-Modified 新鲜度信号；图片优化由 lazyload 与显式尺寸比例组成
结构化数据10%
  • 汇总取值：直接取 schema.structured_data_score，再按 ×0.10 计入综合分
  • 计算公式：JSON-LD + Organization + WebSite + Service + Article + FAQPage + Product + BreadcrumbList + machine dates + sameAs + @id + visible-content alignment
  • 数据来源：优先复用 snapshot 中各页面的 json_ld_blocks，统一汇总 @type、sameAs、稳定 @id、机器可读日期以及 Schema 与页面可见内容的一致性
  • 接入要点：schema 既参与综合分，也被平台适配模块复用，尤其影响 Google AI Mode、AI Overviews 与 Gemini
平台适配10%
  • 汇总取值：直接取 platform.platform_optimization_score，按平台战略权重汇总后再按 ×0.10 计入综合分
  • 平台权重：ChatGPT 22%，Google AI Mode 18%，Google AI Overviews 18%，Perplexity 16%，Gemini 13%，Grok 13%
  • 数据来源：不额外抓取，直接复用 discovery snapshot、visibility、schema 与 metadata 结果
  • 输出结果：分别产出 chatgpt / google_ai_mode / google_ai_overviews / perplexity / gemini / grok 的分数、优化焦点、主缺口与建议
发现层与复用机制
  • 发现层升级：当前 discovery 已升级为 snapshot-v3，默认抓取 homepage、about、service、article、case_study；full audit 时继续扩展到更多内部页
  • 抓取作用域：按“精确 host + 语言路径前缀”限制范围；例如 www.ecoflow.com/de/ 只抓 /de/，不会抓 de.ecoflow.com 或 /fr/
  • 统一画像：每个页面都输出 title、meta、canonical、lang、headings、word_count、FAQ / 作者 / 日期、引用来源区、TL;DR、链接语义、JSON-LD 摘要、entity signals 等统一 profile
  • 复用机制：audit_full 支持直接传入已有 discovery，存在时复用，不再重复执行 discover
  • 提示机制：当输入 URL 不是首页或语言首页时，结果中会增加“非首页，数据可能有偏差”的提示，但不会强制改写输入页
Observation Layer / 不计分
  • 定位：可选上传 GA4、日志或人工引用观测，用于展示实际观测结果，不属于 6 个计分维度
  • 默认行为：大部分用户只输入 url 即可；未上传 observation 时仍可完成完整审计
  • 展示内容：可呈现 AI sessions、来源平台拆分、citation observations 与 measurement maturity
