快速开始

异步任务模式

提交一个 URL，从创建任务开始。结果通过任务 ID 查询。

  1. 创建审计任务

    提交目标 URL，获取 task_id。

  2. 查询任务状态

    每隔 1–2 秒轮询，直到任务完成或失败。

  3. 读取与导出结果

    从 result 读取诊断，按需获取报告和图谱。

cURL创建网站 GEO 审计
curl -X POST \
  "http://localhost:8023/api/v1/tasks/audit" \
  -H "Content-Type: application/json" \
  -H "X-API-Token: YOUR_API_TOKEN" \
  -d '{
    "url": "https://example.com",
    "task_type": "site_geo_only_audit",
    "feedback_lang": "zh"
  }'
想直接发送请求？立即测试 API在交互式文档中查看完整请求与响应定义。

访问认证

启用访问保护时，请在所有 /api/v1/ 业务请求中携带有效 Token。推荐使用 X-API-Token 请求头。

请求头
X-API-Token: YOUR_API_TOKEN

兼容 X-Demo-Token 与 Authorization: Bearer <token>。在 API 调试页面点击 Authorize 填入 Token 即可。

401
Token 缺失或无效，请检查请求头。
429
Token 调用额度已用尽，请检查可用额度。

API 调用步骤

优先使用异步任务；需要独立诊断时，可直接调用单个模块。

创建审计任务

POST/api/v1/tasks/audit

新增 site_geo_only_audit：网站 GEO 审计，执行 discovery → geo → observation → summary。保留 site_geo_audit 表示网站 SEO+GEO 审计，执行 discovery → seo + geo → observation → summary，共享同一批页面证据。

任务类型评分口径结果位置
site_geo_only_audit 网站 GEO 审计站内六维就绪度，onsite-geo-v1；不含外链、OG/Twitter卡片、一般安全响应头或平台推测分result.geo.score / summary.geo_score
site_seo_audit 网站 SEO 审计SEO既有六维、权重按95归一；外链为品牌权威支持信号，OG/Twitter属于技术支持检查result.seo.overall_score / summary.overall_score
site_geo_audit 网站 SEO+GEO 审计分别运行上述两套评分，共享证据但不平均、不合成第三个总分result.seo + result.geo；summary.seo_score 与 summary.geo_score
site_content_audit 网站内容审计单篇内容评分，独立于上述站点评分result.content / result.summary

页面默认首选网站 GEO 审计。为兼容已有调用，API省略 task_type 时仍默认 site_seo_audit；请显式传入所需类型。三种站点任务均按精确 host 与语言路径限制抓取；图谱可选、独立构建。

查询任务状态

GET/api/v1/tasks/{task_id}

建议每隔 1–2 秒查询一次。当 status 为 completed 或 failed 时停止轮询。steps 实时反映各模块的执行状态。

queued→running→completed或failed
字段类型说明
statusstringqueued → running → completed | failed
progress_percentint0–100，按完成步骤数计算
cachedboolean命中缓存时为 true，直接返回历史结果
llm_model_usedboolean只有真正拿到并使用了 llm.model 的增强结果时才为 true；失败降级时为 false
resultobjectcompleted 后按任务类型返回 geo 和/或 seo，以及 discovery、summary；新版GEO还返回 observation 和 page_diagnostics，并在 discovery.scope_root_url、requested_target_locale、resolved_target_locale 中标明语言作用域

获取任务图谱

可选

创建任务时设置 build_knowledge_graph=true。结构图谱与实体图谱复用同一批页面快照，独立异步构建，构建失败不会中断审计。

GET/api/v1/tasks/{task_id}/structure-graph

结构图谱：站点、页面、产品或服务、sameAs、内外链及证据关系。

GET/api/v1/tasks/{task_id}/entity-graph

实体图谱：品牌、产品名、特性、规格、使用场景及评价类文本实体。

导出审计报告

GET/api/v1/tasks/{task_id}/report

网站GEO、SEO及SEO+GEO任务完成后，可获取完整 Markdown 报告；组合报告包含两套独立评分。仅在 status=completed 时可用。

页面证据与导出

获取任务发现的 URL、采样页面的抓取记录，以及 Excel 报告。以下 Demo 接口使用相同的 Token 访问验证。

GET/api/v1/demo/tasks/{task_id}/pages

站点链接与页面抓取记录，包括抓取时间、状态码、响应耗时及部分响应头。未采样或历史缺失的数据标记为“未记录”。

GET/api/v1/demo/tasks/{task_id}/pages/{page_id}/source

读取页面 HTML 源码。page_id 来自对应任务的链接列表；源码以纯文本展示，不随任务轮询重复传输。

GET/api/v1/demo/tasks/{task_id}/export.xlsx

导出当前任务的网站 SEO 审计 Excel 报告。

每份源码最多缓存 2 MB，超限时标记截断。缓存保存在 CACHE_DIR/page-sources。

统一计分与阻断规则

  • 单项 value 在0–1之间；确定性检查为0/1，覆盖型按比例，明确的部分满足可为0.5。每项包含状态、证据、判定方式和建议。
  • 状态分为 pass、partial、fail、unknown、na。不适用项剔除；未检测或证据不足为unknown，绝不当作通过。
  • 维度分 = 已测项加权得分 ÷ 已测适用项满分 × 100；总分按六维固定权重汇总。某维度完全未测时，仅暂算其余维度，并扩大分数上下界；不得给就绪结论。
  • 维度证据覆盖率 = 已测适用分值 ÷ 全部适用分值；总覆盖率按维度权重汇总。score_range下界将未知项设0，上界设1；暂定分由已测项计算。
  • 先逐页计分；页面类型等权，同类型页面等权。候选URL按类型轮询采样；失败页面保留。sample_coverage是已采样/已知候选，total_site_pages未知时不声称全站覆盖。
  • HTTP失败、当前访问挑战、无核心正文、误设noindex或目标检索渠道robots阻断，按页面/渠道列出blockers。readiness_status=blocked不能被高总分抵消；含未知项时provisional=true，不能宣称已验证就绪。
  • 仅全部适用项已核验、无阻断且分数≥85时给ready；其余已核验结果为needs_work。普通分级仍使用0–24、25–44、45–64、65–84、85–100五档。

页面类型与证据边界

  • 商品看名称、说明、规格/报价；文档看主题、解释、步骤/代码/参考；工具看用途、带标签输入与操作；首页/服务/关于/联系页看用途、说明及下一步；文章等看解释与内容分节。无固定字数、标题长度或FAQ强制要求。
  • GEO-012至016是题文关键词覆盖、首段/关键信息位置、指代及标题跳级、任务结构、重复与空泛表达等结构代理，evidence_type=structural_proxy；不等于语义和事实已核验。
  • GEO-018检查被识别的数字/研究/测试主张附近是否有来源链接，不自动确认来源真实性；无此类主张为na。GEO-019按页面类型检查可解析、非未来的日期或适用版本，不能由ETag/Last-Modified推断内容新鲜度。
  • GEO-004单次抓取不足以判断持续稳定性，保留unknown；GEO-020缺少已审核跨页事实清单时保留unknown，不用品牌名称一致冒充事实一致。
  • GEO-011复用可选Chromium渲染；未启用、失败、截断或未验证抓取权限时为unknown。正文直接从main/article/role=main或body提取，剔除导航、页脚、脚本、隐藏节点，不根据字数猜SSR。
  • 默认检查Googlebot、bingbot、OAI-SearchBot、PerplexityBot的目标路径规则，训练许可不计分；模拟请求成功不代表真实AI爬虫或指定地区访问成功。

数据来源与运行机制

汇总层维度业务落成：三种站点任务独立评分

  • 纯GEO不请求Semrush；组合审计通过一次发现、一次页面证据收集，将同一批HTTP响应与源码分别交给SEO和GEO，不重复抓取同一份审计页面。SEO的域名变体探测及可选浏览器渲染属于独立测量。
  • 外链质量属于SEO/外部权威支持数据：现有SEO通过品牌权威支持分间接使用外链；OG/Twitter卡片在SEO技术支持分中使用，不是新版GEO一级维度，也不进入GEO总分。安全响应头保留技术检查，实际阻断访问的问题计入GEO可达性。
  • llms.txt、Content-Signal、LLM-Policy、训练授权、外链、社交卡片、一般安全头、平台推测分均不进入GEO总分。Schema只检查适用性、有效性及可见内容一致，不累计所有类型。
  • 实际收录、真实AI引用、品牌提及、流量与转化作为Observation独立展示；不因缺少这些站外观测扣站内GEO分。
  • SEO保留seo-audit-v1权重和评分含义；组合任务的GEO与纯GEO复用同一个onsite-geo-v1引擎。不得混用两类分数或与历史geo-audit-v3直接横比。
  • 结果缓存按任务类型、评分版本、页面数量、语言、审计模式及GEO渲染开关隔离；force_refresh=true绕过结果和站点快照缓存。渲染需ALLOW_PLAYWRIGHT=true及Chromium；启用后会增加浏览器测量耗时。
  • premium在SEO/内容审计中沿用AI增强；新版GEO分值始终规则驱动，llm_enhanced=false，不以模型推断填补未知事实。
  • 历史/audit/full及五模块仍输出geo-audit-v3，兼容旧接入；旧版引用概率与AI认知百分比属于规则推算，不是观测数据，新任务不输出。
